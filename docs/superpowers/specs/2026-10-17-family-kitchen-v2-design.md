# 家庭厨房 v2 重构设计

- 日期：2026-10-17
- 分支：`feature/v2-family-kitchen`（基于 main @ 3d2aa0b）
- 状态：设计定稿，待实施
- 决策方式：头脑风暴可视化会话（8 屏线框迭代），用户逐项确认

## 1. 定位与信息架构

**产品定位**：自家专用的家庭厨房中枢——记账 + 冰箱管理 + 选菜，涵盖过日子三件事：花钱、存粮、吃饭。

- 使用者：一个小家庭（1~4 人），**不再强调多人协作权限**（现有主账号/成员角色保留但弱化，广场等社交功能删除）。
- 底部导航 5 Tab：**中枢 / 账本 / 冰箱 / 菜谱 / 我**。
- 删除功能：广场（公开菜谱分享）、多币种、存钱罐独立卡片（并入存款钱包）。
- 保留但移位：食本（入口收进「我」页）、订单点单（并入菜谱 Tab 的「今天吃什么」）。

## 2. 中枢首页（hub-A：问候 + 四宫格）

- 宫格点击分别跳：账本 Tab、冰箱 Tab、菜谱 Tab（今天吃什么视图）、菜篮页。

## 3. 账本 v2

### 3.1 三钱包模型

| 钱包 | 含义 | 内容 |
|---|---|---|
| 可支配 | 日常花的钱 | 现金、微信、支付宝、活期等流动账户 |
| 存款 | 存起来的钱 | 定存/储蓄账户，可挂存款目标（进度条） |
| 信用卡 | 刷的钱 | 欠款独立显示（负数红字），含总额度/剩余额度 |

- **资产余额 = 可支配 + 存款**；**净资产 = 资产 − 信用卡欠款**。
- 每笔流水可记到某账户：支出→该账户余额扣减；刷信用卡→欠款增加（剩余额度减少）。
- **存钱动作** = 「🐖存钱」按钮：可支配 −N、存款 +N，生成一笔 `TRANSFER` 类型流水（方向 in/out，可随时取回），不复用现有 SavingService 的多币种存取。
- **信用卡还款** = 同为 `TRANSFER` 流水：从某可支配账户 → 信用卡账户，欠款 −N、该可支配账户余额 −N。信用卡账户页提供「还款」按钮预填此流程。

### 3.2 账本首页（v8 线框定稿）

```
┌──────────────────────────────┐
│ 10月 · 账本            2026 ▾ │
│ ┌─────────┐ ┌─────────┐   │  ← 双资产窄卡(各约屏宽46%)，压矮：
│ │💰资产     ¥128,300│ │💳信用卡  -¥2,400│   │    标题与大金额同行、分项行距1.45、
│ │ 可支配    ¥12,300 │ │ 总额度   ¥50,000 │   │    目标进度3px细线、内边距3px
│ │ 存款     ¥116,000 │ │ 剩余    ¥47,600 │   │
│ │ ▓▓▓▓░░░░ 目标40%  │ └─────────┘   │
│ └─────────┘               │
│ [结余 ¥5,260][收入 ¥6,500][支出 ¥1,240] │  ← 单行三数
│ [＋记一笔][📊预算][🔁周期][🐖存钱][⋯]  │  ← 操作行；⋯=导出/报表/分类管理
│ ↓ 流水（每笔带账户标签）↓       │
│ - 番茄炒蛋 ¥18.5        微信 │
│ ↔ 存钱 ¥1,000                │
└──────────────────────────────┘
```

- 点资产卡 → 账户管理页（增删账户、期初余额、存款目标设置）。
- 点信用卡卡 → 信用卡账户页（账单/还款记录）。
- 顶部固定区目标 ≤ 屏高 30%，流水区 ≥ 60%。

### 3.3 新增能力

- **预算管理**：月总预算 + 分类预算（支出分类维度）；账本首页预算入口进管理页；超支 80% 预警、100% 提醒（本地通知复用现有 pushUnreadNotices 通道）。
- **周期账单**：房租/水电/订阅等固定收支，设周期（月/年）+ 首次日期，到期自动生成流水（服务端每日扫描，幂等）。
- **多账户**：见 3.1；账户增删/改名/期初余额调整；删除账户需先清流水归属（或转为"已删除"保留流水显示）。

### 3.4 保留与兼容

- 保留：AI 小票识别（GLM-4.6V）、分费用、支付方式、PDF 导出、订单自动入账、左滑编辑。
- 删除：多币种（界面与折算逻辑）；存钱罐卡片与 SavingService 旧多币种存取。
- **数据迁移（Flyway V19，sqlite+postgresql 双方言）**：
  - 新表 `accounts`（见 §6）；每厨房自动建默认账户：现金/微信/支付宝/存款（期初 0）。
  - 旧 `savings`（存钱罐）余额按当时汇率折算人民币，并入「存款」账户余额；旧存取记录生成 `TRANSFER` 流水（标注迁移）。
  - 旧流水 `account_id` 为 NULL 时显示"未指定"，可批量补账户。
  - 多币种字段（`currency`/`rate`）保留在表中不再读取，界面统一人民币。

## 4. 冰箱

保留 1.4.2 冰箱化改造全部成果（冷藏/冷冻双层、存放位置、临期提醒、左滑操作、抠图贴纸）。本次只做两件事：

1. 中枢宫格所需「库存数/临期数」复用现有 `/fridge/summary`，无需改后端。
2. **买菜↔冰箱联动**：菜谱做菜完成（订单完成或"今天吃什么"里标记做完）后，已有用料扣减逻辑统一走冰箱（原先只进菜篮），缺的进买菜清单、有的直接扣冰箱库存。涉及后端订单完成钩子扩展，P3 实施。

## 5. 菜谱 = 选菜中枢

菜谱 Tab 重组为两层：

```
┌────────────────────────────┐
│ 🍽 今天吃什么                │
│ ┌────────┐┌────────┐┌────┐ │
│ │晚餐·未定 ││家人点单 ││冰箱 │ │ ← 今日餐位卡（早/午/晚可配）
│ │🎲随机 📋 ││  2单待做││临期荐│ │    随机选菜/家人点单/按临期食材推荐
│ └────────┘└────────┘└────┘ │
│ 📅 一周餐计划         排一周 │
│ 📖 菜谱库（现有列表+分类+管理）│
└────────────────────────────┘
```

- **今天吃什么**：三个来源合一——①随机/收藏挑（现有 random 选菜升级）②家人点单（现有订单流程收进这里）③**冰箱驱动推荐**（按临期食材匹配菜谱用料，展示"再不做就过期"标签）。
- **一周餐计划**：保留现有餐段计划，增强"排完一键生成买菜清单"（现有用料汇总逻辑）。
- **菜谱库**：现有菜谱管理原样下沉。
- 做完标记：任一来源做的菜可标"做完"→ 触发用料扣冰箱/缺料进菜篮 + 订单类自动入账（复用现有）。

## 6. 数据模型变更（服务端）

新增表（V19 迁移，双方言）：

```
accounts          账户：id, kitchen_id, name, type(DISPOSABLE|SAVING|CREDIT),
                  initial_fen, credit_limit_fen(NULL=非信用卡), sort, deleted, created_at
budgets           预算：id, kitchen_id, month(YYYY-MM), category(NULL=总预算),
                  amount_fen, created_at   ← 每月一行，复制上月可一键
recurring_bills   周期账：id, kitchen_id, type(INCOME|EXPENSE), category, amount_fen,
                  account_id, cycle(MONTHLY|YEARLY), next_date, last_entry_id, enabled
saving_goals      存款目标：id, kitchen_id, name, target_fen, deadline(NULL=无期), created_at
```

- `ledger_entries` 增列：`account_id`（NULL=未指定）、`transfer_dir`（'in'/'out'，仅 TRANSFER 类型）。
- 流水类型新增 `TRANSFER`（存钱/取回，不计收支统计）。
- 余额计算：账户余额 = 期初 + 流入流水 − 流出流水（TRANSFER 按方向进出对应账户；信用卡支出=欠款+）。
- 周期账扫描：每日定时（复用现有临期扫描的调度方式），`next_date` 到期生成流水并推进日期，`last_entry_id` 保证幂等。
- 删除：square 模块（Controller/Service/前端页面）；SavingService 多币种逻辑改写为存款目标。

## 8. 决策记录

| 决策 | 结论 | 备选与否决原因 |
|---|---|---|
| 骨架 | 数据仪表盘 5 Tab（中枢/账本/冰箱/菜谱/我） | 曾选「今天」流程主线后改为仪表盘；三大件平级缺总览 |
| 中枢形态 | 问候+四宫格 | 待办焦点型行动感强但偏任务清单；环形仪表炫但指标抽象 |
| 账本首页 | 复用现有+双资产窄卡(v8) | 横滑卡/六子Tab/工具箱均因信息隐藏或拥挤否决；净资产横幅信息量不足 |
| 存钱 | 并入存款钱包，TRANSFER 流水 | 独立存钱罐与存款概念重复，用户明确定义"固定资产就是存的钱" |
| 多币种 | 删除，统一人民币 | 与多账户并存易乱，用户拍板 |
| 广场 | 删除 | 自家专用后无社交需求 |
| 固定资产 | = 存款（不做房车清单） | 用户明确"存的钱"；房车清单 YAGNI |
